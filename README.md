# HTML Visual Editor

一个面向 **产品经理、游戏策划、设计评审与 PPT/HTML 内容维护** 的单文件可视化编辑器。

当前版本：**V3.6.18**

> 无需构建环境，直接用浏览器打开 `index.html` 即可使用。

## 这个工具解决什么问题

很多 HTML 演示稿、网页原型、AI 生成 PPT 或可视化页面，在后续修改时仍然需要直接改代码。  
这个编辑器的目标是把常用修改操作转成可视化操作，让非前端用户也能直接：

- 修改标题、正文、数字、页脚等文字
- 修改字号、颜色、字重、对齐、行高、字间距
- 拖动元素位置、改变宽高
- 编辑底框、边框、圆角、透明度和常用图形
- 编辑表格行列、单元格与文字
- 插入图片、视频、按钮、下拉框等内容
- 管理 PPT/多页面 HTML 的页面顺序
- 直接绘制产品/游戏界面原型，并配置页面跳转与交互
- 导出 HTML、PPTX，以及带本地视频附件的 PDF 包

## 适合的使用场景

### 1. HTML / PPT 可视化修改

适合 AI 生成的 HTML 演示稿、网页式 PPT、内部汇报材料等。  
导入之后可以像编辑设计稿一样修改页面，而不需要手改 HTML/CSS。

### 2. 产品经理 / 游戏策划原型设计

编辑器内置“交互原型设计”工作区，可以创建多个界面，使用组件库快速搭建：

- 页面容器 / 卡片
- 文本 / 图片 / 视频
- 输入框 / 多行输入 / 搜索框
- 下拉列表 / 复选框 / 单选组 / 开关 / 滑杆
- 按钮 / 页签 / 导航栏
- 弹窗 / Tooltip / Toast / 进度条
- 表格 / 图形等

还可以给组件配置“跳转页面”等交互，并在“界面关系”中查看 Screen Flow。

### 3. 带视频的演示稿交付

支持导入本地视频。  
本地视频会以 Data URL 方式保存在导出的 HTML 中；PDF 导出则支持生成：

```
项目_PDF视频包_最终.zip
├─ 项目.pdf
├─ README.txt
├─ 视频清单.txt
└─ videos/
   ├─ video_01.mp4
   ├─ video_02.mp4
   └─ ...
```

PDF 中的视频入口会使用相对路径指向 `videos/` 目录。

## 快速开始

### 直接运行

1. 下载仓库。
2. 双击打开 `index.html`。
3. 建议使用最新版 Chrome 或 Edge。
4. 点击顶部 **“导入 HTML”**。
5. 选择要编辑的 HTML 文件。
6. 点击页面中的元素，在右侧 Inspector 中修改属性。

不需要 Node.js，不需要 npm，也不需要安装依赖。

## 导出

顶部文件栏支持：

### HTML

导出当前编辑结果为 HTML。

### PPTX

提供增强 PPTX 导出，对常见 CSS 底框、透明度、边框、圆角和渐变做近似转换。

复杂 CSS 在 PowerPoint / WPS 中仍可能与浏览器存在差异，因此 PPTX 更适合作为可继续编辑的交付版本，而不是像素级截图版。

### PDF + 视频包

V3.6.18 的 PDF 视频流程采用 **两步式导出**：

1. 点击 **“PDF + 视频包（原生）”**。
2. 编辑器扫描当前画布中的视频，并打开浏览器原生打印页。
3. 在浏览器打印窗口选择 **“另存为 PDF”**。
4. 保存 PDF 后回到编辑器。
5. 点击 **“选择已保存 PDF”**。
6. 选择刚才保存的 PDF。
7. 编辑器会：
   - 给 PDF 中每个视频写入相对文件链接
   - 打包本地视频
   - 生成最终 ZIP

### PDF 视频包注意事项

- 必须先完整解压 ZIP。
- PDF 与 `videos/` 文件夹需要保持同级。
- 不要直接在压缩包预览模式中打开 PDF。
- WPS / Acrobat 第一次打开本地视频链接时可能弹出安全确认。
- 网络视频如果受 CORS 限制无法下载，会保留 URL 引用说明。
- V3.6.18 会检查“检测到的视频数量”和“实际打包的视频文件数量”，避免生成看似成功但视频缺失的不完整包。

## 版本管理

编辑器会保留原始导入版本，并支持 **“保存新版本”**。

每次保存都会生成新的版本记录，不覆盖原始文件，适合反复调整 PPT / 页面时回退。

## 已知限制

1. 极复杂的第三方网页、跨域 iframe、强依赖运行时框架的页面，不保证可以完全编辑。
2. PPTX 不等于浏览器 CSS 渲染器，复杂滤镜、mask、混合模式等效果可能需要近似处理。
3. PDF 本地文件链接是否直接打开，受 WPS / Acrobat / 浏览器安全策略影响。
4. 远程视频是否可以直接打包，受 CORS 与资源服务器权限影响。
5. 单文件内嵌大体积视频后，HTML 文件体积会显著增加。

## 开发方式

当前版本采用 **单文件 HTML 架构**，核心 CSS、JS 与所需库均打包在 `index.html` 中。

如果后续继续迭代，建议保持：

- `index.html` 始终指向当前稳定版本
- 重要版本在 CHANGELOG 中记录
- PDF / PPTX / 视频链路修改后优先做多页、多视频回归测试
